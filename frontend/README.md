# AI-buddy — фронтенд

React + TypeScript + Vite. Папка `frontend/`, рабочая ветка `frontend`.
Интерфейс получает профиль, задачи, результаты, источники и прогресс от Go API.
Подставленных ответов ИИ и имитации успешного сохранения во фронтенде нет.

## Запуск

Требуется Node.js 20.19+ или 22.12+. Из папки `frontend/`:

```sh
npm ci
npm run dev
```

Отдельно запустите бэкенд по [его инструкции](../backend/README.md).
В корне командного репозитория для тестового режима предусмотрено:

```sh
docker compose up --build -d
```

Сервер должен отвечать на `http://127.0.0.1:8080/ready`. Секреты для replay не нужны.
Если сервер выключен, интерфейс покажет ошибку подключения и кнопку повтора.

## Адрес сервера

По умолчанию Vite проксирует `/api` на `http://127.0.0.1:8080`, поэтому менять CORS
бэкенда для порта Vite не требуется. При другом адресе скопируйте `.env.example`
в `.env.local`, измените `BACKEND_PROXY_TARGET` и перезапустите Vite.

Для собранного сайта нужен reverse proxy `/api` к Go. Другой вариант — задать
`VITE_API_BASE_URL` при сборке и разрешить origin сайта через `CORS_ORIGINS` в Go.
`VITE_` переменные публичны: ключи моделей и служебные токены в них не размещают.

## Что подключено

Контракт: [backend-openapi.yaml](../specs/backend-openapi.yaml).

- Профиль из `GET /api/v1/me`. API пока не отдаёт команду, поэтому вымышленная команда не показывается.
- Список доступных тестовых задач из `GET /api/v1/demo/issues`; можно ввести номер из списка или ссылку Jira.
- Создание анализа и опрос статуса раз в две секунды, только пока `queued` или `collecting_context`.
- Факты, гипотезы, цитаты, ограничения и план из результата сервера.
- Ответ на уточнение через `/answers`; текст сохраняется в поле при ошибке.
- Материал по `/sources/{source_id}` с указанием версии. При отказе в доступе старое превью не показывается.
- Галочки через PATCH `/steps/v{revision}-s{number}`; локально изменяются только после подтверждения.
- Кнопка «Сохранить в Jira» отправляет `confirmed: true` и текущую версию на `/publish`.
  Успех и ссылка появляются после ответа API. Сейчас Go сохраняет в тестовую Jira, не в корпоративную.
- Ключи идемпотентности повторно используются при повторе той же неудавшейся операции.
- При обрыве опроса можно обновить уже созданный разбор, не создавая другой.
- Запросы отменяются при закрытии компонента; старые ответы не заменяют новую задачу.

В `AI_MODE=replay` бэкенд возвращает записанные результаты. DEMO-1 подходит для
готового плана; DEMO-2 — для вопросов. Текущий Go-код отклоняет ответы на уточнения
в replay (`replay_input_not_recorded`). Интерфейс показывает эту ошибку, не придумывает
обновлённый план. Для проверки полного цикла уточнений нужны live или доработка replay
на стороне бэкенда. Тестовые данные сервера сохранены, фронтенд их не дублирует.

## Файлы и проверки

- `src/api/task-api.ts` — запросы, ошибки и опрос статусов.
- `src/api/task-view.ts` — преобразование ответа в данные компонентов.
- `src/types/api.ts` — типы контракта Go.
- `src/components/task-workspace.tsx` — действия пользователя и рабочая область.

```sh
npm run build
npm run lint
npm test
```

Для `npm test` нужен Node.js 22.6+ (встроенный запуск TypeScript). Тесты проверяют
контракт запросов, версии, ошибки, ссылки и отмену опроса. Они не вызывают модель.

Переключение вкладок сохраняет черновик ответа. Tab/Shift+Tab перемещают фокус,
стрелки/Home/End переключают вкладки, пробел отмечает шаг.
