# SDD: Python AI Task Navigator

Основание: AI_buddy_Task_Navigator.pdf и кейс Авито, предоставленные командой.
Область ответственности: Python AI-сервис на схеме. Go API/Worker получает
задачу из Jira, авторизует пользователя, хранит результат в PostgreSQL и после
подтверждения пользователя сохраняет план в Jira. AI-сервис возвращает результат
анализа и текст плана. Успешный анализ не означает успешное сохранение в Jira.

## Контракт

`POST /v1/analyze`, заголовок `Authorization: Bearer <AI_SERVICE_TOKEN>`.
Вход: task_id, title, description, acceptance_criteria, allowed_scopes, question.
Go вычисляет allowed_scopes из прав пользователя, а не копирует их из браузера.
Токен AI-сервиса известен только Go Worker. Python доступен во внутренней сети.
Повторное уточнение: Worker передаёт исходную задачу и ответ пользователя в question.

Выход: task_id, status, plan, sources, model, usage, jira_markdown.
Plan: summary, findings (fact/hypothesis и роль), steps, questions, limitations.
Каждая цитата указывает source_id, start_line, end_line и точный текст quote.
Source содержит путь и фактически просмотренный снимок текста: фронтенд может
открыть этот снимок по source_id и подсветить строки, не доверяя ссылкам от LLM.
Снимок позволяет проверить результат даже после изменения исходного файла.

## Поведение и приёмка

1. Источники фильтруются по allowed_scopes до поиска; закрытый текст не попадает
   в LLM, результаты, ошибки или запрос расширения поисковых терминов.
2. LLM переводит термины задачи в русский/английский поисковый словарь.
   Локальный индекс ранжирует разрешённые документы по взвешенным словам.
   Не более 8 источников корпуса / 45000 символов. Дополнительно передаётся
   снимок входной задачи task:<task_id> (суммарный текст задачи до 28000 символов).
   При отборе сохраняются контракт события и найденные фрагменты отправителя/
   получателя. Совпадение имени события — повод изучить источник, не доказательство связи.
3. LLM получает задачу и найденные код, документацию, контракты и тесты.
   Инструкции внутри источников рассматриваются как данные. У модели нет
   инструментов записи файлов, выполнения команд или обращения в Jira.
4. Факты требуют цитат. Проверяются существование источника, диапазон строк
   и буквальное наличие цитаты. Номер строки для уникальной дословной цитаты
   вычисляется кодом; для неоднозначной или выдуманной цитаты место не угадывается.
   Модель получает номера строк и список допустимых source_id.
   После невалидного плана — одна попытка
   исправления с конкретной ошибкой и предыдущим ответом, затем 502 llm_ungrounded_response.
5. Вопросы или отсутствие полезного плана → needs_clarification.
   Нет разрешённого найденного контекста → insufficient_context.
   План с findings/steps без вопросов → ready (готов к рассмотрению человеком).
6. Отсутствие источников не доказывает отсутствие сервиса.
7. Нет ключа/служебного токена → 503; неправильный служебный токен → 401;
   невалидный вход → 422; тайм-аут LLM → 504; ограничение частоты → 503;
   иные ошибки провайдера → 502. Сырые ошибки и ключи клиенту не раскрываются.
8. Worker выставляет collecting_context перед запросом, сохраняет ответ и
   выставляет его status. Ошибку хранит отдельно. UI опрашивает Go, не ждёт LLM
   синхронно. После согласия пользователя Go пишет jira_markdown в Jira,
   сохраняет идентификатор/ссылку ответа и только тогда выставляет saved.

## Границы и оценка

Локальный JSON-корпус — имитация разрешённых корпоративных источников.
Корпус воспроизводимо строится из явного manifest и 21 файла fixtures.
Отдельный CLI-стенд DemoJira читает 6 задач, ограничивает scopes профилем,
после подтверждения сохраняет готовый план в SQLite и возвращает квитанцию.
Повтор идентичного ответа не создаёт дубль. Это заменяемая имитация для показа,
не реализация командного Go API. См. docs/demo.md.
Промышленный GitLab/Wiki-коннектор, обновление индекса и пользовательские ACL
должны поставлять тот же формат Source; реальные доступы не предоставлены.
Поиск лексический: семантическая полнота не гарантируется. Подлинность цитаты
проверяется автоматически; логическое следование утверждения из цитаты — нет.
Промпт не является полной защитой от prompt injection; инструменты действий
отсутствуют, ACL проверяется кодом. Учёт затрат — usage, без оценки стоимости.
Тайм-аут до 90 секунд на вызов; до трёх вызовов (расширение, план, исправление).
Worker должен иметь тайм-аут >270 секунд либо отдельное управление job.

Автотесты: поиск/ACL, корректный план, нехватка доступа, неоднозначность,
выдуманные цитаты, repair, валидация API, ошибки/тайм-ауты провайдера.
Минимальное покрытие >80%. Реальный smoke-тест отделён от тестов без сети.
Метрики пилота: точность ссылок и межсервисных связей, доля корректных первых
шагов, время поиска, количество оставшихся рутинных вопросов наставнику.
Сравнение: без помощника, обычный чат с тем же контекстом, Task Navigator.
