# Демонстрация без корпоративных данных

Эта страница описывает отдельный Python CLI-стенд. Для полного приложения
React + Go + PostgreSQL используйте [README](../README.md) и
[ручную приёмку](testing.md). CLI хранит mock Jira в SQLite; веб-приложение —
в PostgreSQL. Записи этих двух стендов не общие.

Это вымышленный учебный маркетплейс. LLM настоящая: Qwen 3.8 Flash через Polza.
Код, документы, Jira-задачи и пользователи синтетические, это не данные Авито.

## Комплект

- 21 источник в `fixtures/`: код, контракты событий, документация, тестовые
  сценарии, история задачи и каталог. Go-фрагменты — материал для анализа,
  не запускаемые микросервисы.
- `data/source_manifest.json`: явный список индексируемых файлов и прав.
  `.env` и эталоны оценивания не индексируются.
- `data/demo_tasks.json`: 6 задач и 3 профиля для команды Go.
- `data/evaluation_cases.json`: ожидаемые источники, статусы и ручная рубрика.
  Эти эталоны не передаются LLM.
- `navigator/demo_jira.py`: отдельная локальная имитация хранения планов в
  SQLite для показа Python-части; Go может заменить её своей реализацией.

| Задача | Что демонстрирует | Ожидаемый статус |
|---|---|---|
| DEMO-1 | Отмена продавцом, согласованный email и защита от повторов | ready |
| DEMO-2 | Не определены канал, причины и получатель уведомления | needs_clarification |
| DEMO-3 | Событие доставки не меняет статус заказа | ready |
| DEMO-4 | Нет доступных источников | insufficient_context |
| DEMO-5 | Критерий задачи противоречит документу | needs_clarification |
| DEMO-6 | В найденном комментарии есть посторонние инструкции | ready |

`intern` имеет scope demo; `newcomer` — без доступов; `reviewer` —
demo/restricted/legacy/adversarial. DEMO-5/6 для полного набора источников
запускаются с `--profile reviewer`. Имена профилей CLI — имитация ролей,
не настоящая авторизация. В рабочем API права подтверждает Go.

## Показать путь от задачи до сохранения

Из корня проекта, `.env` уже настроен:

```powershell
# Готовый показ без сети — явно обозначенный replay реального ответа:
.\.venv\Scripts\python.exe -X utf8 scripts/walkthrough.py --case DEMO-1 --replay examples/recorded/DEMO-1.json

# Получить задачу из имитации Jira и выполнить настоящий анализ:
.\.venv\Scripts\python.exe -X utf8 scripts/walkthrough.py --case DEMO-1

# Проверить все задачи настоящей моделью и сохранить ответы:
.\.venv\Scripts\python.exe scripts/evaluate.py --live

# После просмотра явно подтвердить сохранение ранее полученного ответа:
.\.venv\Scripts\python.exe -X utf8 scripts/walkthrough.py --case DEMO-1 --replay examples/recorded/DEMO-1.json --confirm-save

# Прочитать запись; ID берётся из квитанции предыдущей команды:
.\.venv\Scripts\python.exe -X utf8 scripts/walkthrough.py --read-plan 1
```

`--replay` обозначает повтор ранее полученного ответа и не вызывает LLM.
`--confirm-save` — явное подтверждение записи. Без него план только показывается.
Для needs_clarification/insufficient_context сохранение финального плана отклоняется.
Повторное сохранение такого же ответа тем же профилем возвращает существующий ID;
изменённый результат создаёт новую запись.

Квитанция содержит `status: saved`, ID, путь базы и `demo-jira://...`.
Это внутренний идентификатор, не веб-ссылка Jira; просмотр через `--read-plan`.
База `artifacts/demo-jira.sqlite3` переживает перезапуск скрипта.
Действие в имитации сервиса действительно выполняется и проверяется чтением.

## Проверка без сети

```powershell
.\.venv\Scripts\python.exe scripts/build_corpus.py
.\.venv\Scripts\python.exe scripts/evaluate.py
.\.venv\Scripts\python.exe -m pytest -q --basetemp=artifacts/tmp-tests --cov=navigator --cov=scripts --cov-report=term-missing --cov-report=xml:artifacts/coverage.xml --cov-fail-under=81
```

Обычный evaluate проверяет поиск по фиксированным запросам, не LLM.
`--live` проверяет всю цепочку и расходует баланс. `--case DEMO-3` ограничивает
проверку одной задачей. Результаты: `artifacts/evaluation/` (исключены из Git).
При переиспользовании старых ответов сверяйте итоговый live.json: отдельный файл
ответа может относиться к предыдущему успешному запуску.

Проверяются ожидаемые источники, ACL, буквальные цитаты, статус, минимальное число
выводов/вопросов и отсутствие контрольных строк в плане. Recall — число найденных
обязательных источников, делённое на их число в эталоне. Это не доля правильных
рассуждений. Ручная рубрика нужна для оценки связей, первого шага и вопросов.
Шесть синтетических задач не доказывают качество на промышленном репозитории.

## Передача Go-разработчику

1. Использовать issues из demo_tasks.json как ответы имитации Jira, profiles —
   как тестовые права. Scopes legacy/adversarial не включать обычному стажёру.
2. Отправить задачу в `POST /v1/analyze`. allowed_scopes вычисляет Go как
   пересечение прав пользователя и области задачи.
3. Сохранить ответ AI, показать plan/sources и вопросы. При уточнении повторно
   передать задачу с ответом пользователя в question.
4. После согласия пользователя сохранить jira_markdown в свою имитацию Jira,
   вернуть и сохранить ID/ссылку. Успешный ответ LLM не заменяет это действие.

CLI использует ту же логику анализа, что API. Интеграцию фронтенда и Go Worker
нужно проверить отдельно. HTTP-контракт: specs/openapi.json.
